## 1. Problem Statement

Given an integer array `nums` of size `n`, return the minimum number of moves required to make all array elements equal.

In one move, you can increment exactly `n - 1` elements of the array by `1`.

### Example 1

**Input:**
```text
nums = [1, 2, 3]
```

**Output:**
```text
3
```

**Explanation:**

```text
[1, 2, 3]
[2, 3, 3]
[3, 4, 3]
[4, 4, 4]
```

Three moves are required.

### Example 2

**Input:**
```text
nums = [1, 1, 1]
```

**Output:**
```text
0
```

All elements are already equal.

---

## 2. Approach: Mathematical Transformation

### Key Observation

The most important observation is:

**Incrementing `n - 1` elements by 1 is equivalent to decrementing exactly one element by 1, as far as relative differences between elements are concerned.**

Why?

Consider the original array:

```text
[1, 2, 3]
```

Original operation: Increment the first two elements.

```text
[1, 2, 3] → [2, 3, 3]
```

Equivalent operation: Decrement the last element.

```text
[1, 2, 3] → [1, 2, 2]
```

Notice that both resulting arrays differ by a common offset of 1.

```text
Actual:     [2, 3, 3]
Equivalent: [1, 2, 2]
Difference: [1, 1, 1]
```

Adding or subtracting the same value from every element does not change their relative differences or whether they are equal.

Therefore, we can transform the original problem into:

**Find the minimum number of operations required to decrement individual elements until all elements become equal.**

---

## 3. Deriving the Optimal Solution

Once we transform the operation, the problem becomes straightforward.

We need to decrement elements until all of them reach the minimum element.

Why the minimum?

- We can only decrement elements in the equivalent problem.
- Therefore, the final equal value cannot be greater than the original minimum.
- Choosing a value smaller than the minimum would require additional operations.
- Hence, the minimum element is the optimal target.

### Example

```text
nums = [1, 2, 3]
```

Minimum element = `1`

| Element | Target | Required decrements |
|---|---|---|
| 1 | 1 | 0 |
| 2 | 1 | 1 |
| 3 | 1 | 2 |

Total moves:

```text
0 + 1 + 2 = 3
```

### Mathematical Formula

Let:

- `n` = Number of elements
- `minElement` = Minimum element in the array
- `sum(nums)` = Sum of all array elements

Each element needs `nums[i] - minElement` decrements.

Therefore:

\[
Moves = \sum_{i=0}^{n-1}(nums[i]-minElement)
\]

Expanding:

\[
Moves = \sum nums[i] - n \times minElement
\]

**Final formula:**

\[
\boxed{Moves = Sum(nums)-n \times min(nums)}
\]

## 4. Java Solution (Primary)

### Approach 1: Find Minimum and Calculate Differences

```java
class Solution {
    public int minMoves(int[] nums) {

        // Step 1: Find the minimum element
        int minElement = nums[0];

        for (int num : nums) {
            minElement = Math.min(minElement, num);
        }

        // Step 2: Calculate the total moves
        int moves = 0;

        for (int num : nums) {
            moves += num - minElement;
        }

        // Step 3: Return the result
        return moves;
    }
}
```

### Code Explanation

**Step 1: Find the minimum element**

```java
int minElement = nums[0];

for (int num : nums) {
    minElement = Math.min(minElement, num);
}
```

- Initialise `minElement` with the first array element.
- Iterate through the array using an enhanced for loop.
- `Math.min()` returns the smaller of two values.
- After iteration, we have the smallest element.

**Step 2: Calculate the moves**

```java
int moves = 0;

for (int num : nums) {
    moves += num - minElement;
}
```

For every element, calculate the difference between that element and the minimum.

This difference represents the number of decrements required to bring the element down to the minimum in our equivalent problem.

**Step 3: Return the result**

```java
return moves;
```

The sum of all differences gives the minimum number of moves.

## 5. Alternative Java Solution (Optimised Formula)

We can calculate the answer directly using the mathematical formula.

```java
class Solution {
    public int minMoves(int[] nums) {

        int minElement = nums[0];
        int sum = 0;

        for (int num : nums) {
            minElement = Math.min(minElement, num);
            sum += num;
        }

        return sum - nums.length * minElement;
    }
}
```

Both Java implementations have the same asymptotic complexity.

**Java note:** For the original LeetCode problem, the `int` implementation is accepted. In generalised problems with potentially larger totals, use `long` for intermediate arithmetic to avoid integer overflow.

## 8. Complexity Analysis

Let `n` be the number of elements.

| Complexity | Value | Explanation |
|---|---|---|
| Time Complexity | O(n) | Two linear traversals of the array |
| Auxiliary Space | O(1) | Only a fixed number of variables are used |

### Why O(n)?

1. Finding the minimum element takes O(n).
2. Calculating the total differences takes O(n).
3. Total = O(n) + O(n) = O(2n) = O(n).

The solution is optimal because every element needs to be examined.

---

## 9. Why Does This Solution Work?

The correctness of this solution depends on the operation transformation.

Every original operation increments all but one element.

Equivalently, we can decrement the excluded element by one because the resulting arrays differ only by a common offset.

After repeatedly applying this transformation:

- Every element can be decremented independently.
- The final equal value cannot exceed the original minimum.
- The minimum is therefore the largest possible common target.
- Choosing this target minimises the total number of decrements.

Thus, the minimum number of moves is:

\[
\boxed{\sum nums[i]-n \times min(nums)}
\]

## 10. Pattern Recognition and Generalisation

### Pattern: Mathematical Observation / Operation Transformation

The main learning from this problem is not the formula. It is recognising that an operation can sometimes be transformed into an equivalent operation that makes the problem easier.

### Questions to Ask When Solving Similar Problems

1. Can I represent the given operation differently?
2. Can I reduce the number of elements affected by each operation?
3. Do relative differences remain unchanged?
4. Can I calculate the answer directly without simulating every operation?
5. Is there a mathematical property that gives the optimal target?

### When Can This Pattern Be Useful?

Look for problems involving:

- Making all array elements equal.
- Minimum operations to equalise values.
- Incrementing multiple elements simultaneously.
- Decrementing individual elements.
- Preserving relative differences between elements.
- Calculating minimum operations using mathematical formulas.

**Important:** This exact transformation works because every operation increments all elements except one by the same amount. It cannot be applied blindly to arbitrary array operations.

## 11. Common Mistakes and Edge Cases

| Scenario | Expected Behaviour |
|---|---|
| All elements are equal | Return 0 |
| Single-element array | Return 0 |
| Negative elements | The approach still works |
| Duplicate minimum elements | Their contribution is 0 |
| Large values | Consider integer overflow in generalised versions |

### Important Mistake to Avoid

Do not simulate the original operations.

A direct simulation would require potentially millions or billions of operations.

Instead, derive the answer mathematically in O(n) time.
