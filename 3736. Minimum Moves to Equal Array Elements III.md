## 1. Problem Statement

Given an integer array `nums`, return the minimum total number of moves required to make all elements equal.

In one move, you may increase any single element by 1.

### Example 1

**Input:**
```text
nums = [2, 1, 3]
```

**Output:**
```text
3
```

**Explanation:**

```text
[2, 1, 3]
[3, 1, 3]
[3, 2, 3]
[3, 3, 3]
```

### Example 2

**Input:**
```text
nums = [4, 4, 5]
```

**Output:**
```text
2
```

**Explanation:**

```text
[4, 4, 5]
[5, 4, 5]
[5, 5, 5]
```

## 2. Approach: Greedy + Mathematical Observation

### Key Observation

**When we can only increment array elements, the optimal target is the maximum element in the array.**

Why?

- We cannot decrease any element.
- Therefore, the final common value cannot be smaller than the original maximum.
- Choosing a target greater than the maximum would require unnecessary additional operations.
- Hence, the maximum is the smallest feasible common target.

### Example

```text
nums = [2, 1, 3]
```

Maximum element = `3`

We need to increase every other element until it reaches 3.

| Element | Target | Required moves |
|---|---|---|
| 2 | 3 | 1 |
| 1 | 3 | 2 |
| 3 | 3 | 0 |
| Total | | 3 |

## 3. Mathematical Formula Derivation

Let:

- `n` = Number of elements.
- `maxElement` = Maximum element.
- `sum` = Sum of all elements.

Every element needs:

\[
maxElement-nums[i]
\]

increments.

Therefore:

\[
Moves=\sum_{i=0}^{n-1}(maxElement-nums[i])
\]

Expanding:

\[
Moves=n\times maxElement-\sum nums[i]
\]

### Final Formula

\[
\boxed{Moves=n\times max(nums)-sum(nums)}
\]

## 4. Java Solution (Primary)

### Optimal Approach

Find the maximum element and the sum of all elements in a single traversal.

```java
class Solution {
    public int minMoves(int[] nums) {

        int maxElement = nums[0];
        long sum = 0;

        // Find maximum and calculate sum
        for (int num : nums) {
            maxElement = Math.max(maxElement, num);
            sum += num;
        }

        // Calculate minimum moves
        long moves = (long) nums.length * maxElement - sum;

        return (int) moves;
    }
}
```

### Code Explanation

**Step 1: Initialise variables**

```java
int maxElement = nums[0];
long sum = 0;
```

- `maxElement` stores the largest element.
- `sum` stores the total of all elements.
- `long` is used for safe intermediate arithmetic.

**Step 2: Find maximum and calculate sum**

```java
for (int num : nums) {
    maxElement = Math.max(maxElement, num);
    sum += num;
}
```

Both calculations happen in the same traversal.

**Step 3: Calculate moves**

```java
long moves = (long) nums.length * maxElement - sum;
```

Apply the derived mathematical formula.

**Step 4: Return the answer**

```java
return (int) moves;
```

The LeetCode return type is `int`; the problem's constraints must guarantee that the answer fits.

## 8. Correctness Explanation

Let the maximum element be `M`.

Since we can only increment elements, the final common target `T` must satisfy:

\[
T\geq M
\]

The total moves for a target `T` are:

\[
Moves(T)=\sum_{i=1}^{n}(T-nums[i])
\]

Rearranging:

\[
Moves(T)=nT-\sum nums[i]
\]

The original sum and array length are constant.

Therefore, the number of moves increases as the target increases.

To minimise the moves, choose the smallest feasible target:

\[
T=M
\]

Hence:

\[
\boxed{MinimumMoves=n\times max(nums)-sum(nums)}
\]

This proves that choosing the maximum element is optimal.

## 9. Pattern Recognition and Generalisation

### Pattern: Greedy + Mathematical Observation

Whenever a problem asks you to equalise array elements, first understand which operations are permitted.

| Allowed Operation | Optimal Target |
|---|---|
| Only increment | Maximum |
| Only decrement | Minimum |
| Increment or decrement | Median |
| Increment n-1 elements simultaneously | Minimum (after operation transformation) |

### Questions to Ask

1. Can elements be decreased?
2. Can elements only be increased?
3. What is the smallest feasible common target?
4. What is the largest feasible common target?
5. Can I derive the answer directly without simulating operations?

**Important:** These target-selection rules depend on the operation costs and constraints. They should not be blindly applied to problems with weighted operations or additional restrictions.

## 11. Common Mistakes and Edge Cases

| Scenario | Expected Result |
|---|---|
| Single element `[5]` | 0 |
| Already equal `[4, 4, 4]` | 0 |
| `[2, 1, 3]` | 3 |
| `[4, 4, 5]` | 2 |
| Negative values `[-3, -1, -2]` | 3 |

Common mistakes:

1. Choosing the minimum instead of the maximum.
2. Trying to decrease elements even though the operation does not allow it.
3. Simulating every increment instead of using the formula.
4. Ignoring integer overflow in intermediate calculations.
